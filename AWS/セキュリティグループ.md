# セキュリティグループ

https://tryhackme.com/room/thewideopensecuritygroup

## 基礎概念

- ステートフル：受信ルールでトラフィックが許可されると、戻りトラフィックも自動的に許可されます。これに対し、NACLはステートレスであるため、受信接続と送信接続の両方に対してトラフィックルールを指定する必要があります。
- 許可のみ：SGには暗黙の拒否機能があり、パッケージが定義されたルールに一致しない場合は破棄されます。
- インスタンスレベル：SGはインスタンスのElastic Network Interface（ENI）にアタッチされます。各ENIにはデフォルトで最大5つのSGを設定でき、トラフィックのマッチング時にはすべてのルールが組み合わされます。

## 列挙

実行中のすべてのEC2インスタンス

```sh
aws ec2 describe-instances \
    --filters "Name=instance-state-name,Values=running" \
    --query "Reservations[].Instances[].{InstanceId:InstanceId,Name:Tags[?Key=='Name']|[0].\
Value,SecurityGroups:SecurityGroups[0].GroupName,SubnetId:SubnetId,PrivateIp:PrivateIpAddress,\
PublicIp:PublicIpAddress}" \
    --output table
```

```sh
WEB_SG_ID=$(aws ec2 describe-security-groups --filters \
'Name=group-name,Values=thm-web-app-sg' --query 'SecurityGroups[0].GroupId' --output text)
```

セキュリティグループのルール確認

```sh
aws ec2 describe-security-groups \
    --filters "Name=group-name,Values=thm-web-app-sg" \
    --query "SecurityGroups[].{GroupId:GroupId,GroupName:GroupName,InboundRules:IpPermissions}" \
    --output json
```

表形式

```sh
aws ec2 describe-security-group-rules \
    --filters "Name=group-id,Values=$WEB_SG_ID" \
    --query "SecurityGroupRules[].{Protocol:IpProtocol,FromPort:FromPort,\
    ToPort:ToPort,Source:CidrIpv4,Description:Description}" \
    --output table
```

## 操作

セキュリティグループから一部のルールを削除

```sh
aws ec2 revoke-security-group-ingress \
    --group-id $WEB_SG_ID \
    --protocol tcp \
    --port 22 \
    --cidr 0.0.0.0/0
```

ルールの置き換え。  
削除した後に、特定のSGのみ許可する。つまり、送信元のEC2インスタンスのElastic Network Interface（ENI）にそのセキュリティグループがアタッチされていたら許可されるという形。

```sh
aws ec2 revoke-security-group-ingress \
    --group-id $DB_SG_ID \
    --protocol tcp \
    --port 3306 \
    --cidr 0.0.0.0/0

aws ec2 authorize-security-group-ingress \
    --group-id $DB_SG_ID \
    --protocol tcp \
    --port 3306 \
    --source-group $WEB_SG_ID
```
