# 権限昇格検出（アクセストークン）

https://tryhackme.com/room/identifyingaccesstokenescalation

## 基礎

### アクセストークンとは

認証を行うと、ローカルセキュリティ機関はログオンセッションを作成し、それを参照するアクセストークンを発行する。起動するプロセスごとに独自の派生トークンが生成され（複数のプロセスが1つのセッションを共有できる）、Windowsは、ユーザーが誰であるかを再確認するのではなく、このトークンを読み取ることでアクセス権限を決定する。

トークンはプロセスが持つバッジのようなもので、アクセスチェックではその内容を読み取るだけ。バッジが所持者のものであるかどうかは一切チェックされない。

### トークンの中身

| **Part of the token** | **What it holds**                              | **Why it matters for escalation**                                  |
| :-------------------- | :--------------------------------------------- | :----------------------------------------------------------------- |
| User SID              | アカウント固有の ID                            | Windows がそのプロセスの実行主体として認識するアカウント           |
| Group SIDs            | アカウントが所属するグループ                   | Administrators などのグループへの所属がここで決まる                |
| Privileges            | `SeImpersonatePrivilege` などの名前付き権限     | 一部の権限はファイルやオブジェクトのアクセス許可を直接上書きする     |
| Integrity level       | Low、Medium、High、System                      | 読み取り可能な対象ではなく、変更可能な対象を制限する                |
| Token type            | Primary または Impersonation                   | Impersonation トークンにより、スレッドが別のユーザーとして動作できる |
| Impersonation level   | Identification または Impersonation            | Identification レベルではユーザーの識別のみ可能で、ユーザーとして動作できるのは Impersonation レベルのトークンのみ |
| Logon session         | トークンの元となったログオンセッション         | 調査時にイベント同士を関連付けるために使用する                     |

### 特権

- SeBackupPrivilege、SeRestorePrivilege、SeDebugPrivilege、SeTakeOwnershipPrivilege の特権は、ACLをバイパスする。
- SeImpersonatePrivilege、SeAssignPrimaryTokenPrivilege はプロセスが別のユーザーのセキュリティコンテキストを引き継ぎ、そのユーザーとしてACLチェックされる。

Disabledは特権が無いことを意味しない。AdjustTokenPrivileges呼び出しでアクティブに切り替えることができる。切り替えは、Securityイベント 4703に記録される。

```ps
PS C:\> whoami /priv
...
SeAssignPrimaryTokenPrivilege Replace a process level token              Disabled
```

### 整合性レベル

プロセスは通常、自身のレベルより上のレベルにあるものを変更することはできない（ただし、通常は上位レベルの情報を読み取ることはできる）。そのため、中レベルのプロセスがシステムレベルのプロセスを密かに書き換えることはできない。

### 悪用実行例

```ps
PS C:\> .\PrintSpoofer64.exe -i -c cmd.exe

PS C:\> .\GodPotato-NET4.exe -cmd "cmd /c whoami"
```

### サブテクニックとそれが残す痕跡

| **Method**                 | **MITRE**                                                   | **What it does**                                                                                                  | **Trace it leaves**                                                                                 |
| :------------------------- | :---------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------- |
| Token Impersonation/Theft  | [T1134.001](https://attack.mitre.org/techniques/T1134/001/) | 実行中のプロセスからトークンを複製し、そのユーザーとして動作する。すべての Potato ツールが実行する偽装処理 | 作成元のプロセスがサービスアカウントである SYSTEM プロセス（Sysmon Event 1 + Security 4688 のプロセス系譜） |
| Create Process with Token  | [T1134.002](https://attack.mitre.org/techniques/T1134/002/) | 盗んだトークンを使用して新しいプロセスを起動する。Potato 系ツール（PrintSpoofer、GodPotato）の最終的な動作 | 4688 の Creator はサービスアカウントであり、新しいプロセスは SYSTEM 固有のセッション（`0x3E7`）で実行される |
| Make and Impersonate Token | [T1134.003](https://attack.mitre.org/techniques/T1134/003/) | `LogonUser` を使用し、既知の認証情報からトークンを生成する | ログオンタイプ 9（イベント 4624）。正規の `runas /netonly` でも発生するため、他のイベントとの相関分析が必要 |
| Parent PID Spoofing        | [T1134.004](https://attack.mitre.org/techniques/T1134/004/) | 偽装した親プロセスを指定してプロセスを起動し、ツール本来のプロセスツリーではなく、正規のプロセスツリーに紛れ込ませる | 親 PID が実際の作成元と一致しない（Sysmon 1 の ParentImage / 4688 の不一致） |
| SID-History Injection      | [T1134.005](https://attack.mitre.org/techniques/T1134/005/) | アカウントの SID-History に SID を追加して、追加のグループ所属を取得する。ドメイン内での永続化手法 | SID-History への SID の追加（Security 4765 / 4766） |

## イベントログ

デフォルトで有効なのは 4672 のみ。

| **Log Source** | **Event ID** | **監査設定・発生条件** | **記録内容・用途** | **検出上の注意点** |
| :--- | :--- | :--- | :--- | :--- |
| Security | `4688` | Audit Process Creation（プロセス作成の監査）を有効化 | プロセスの起動を記録する。コマンドラインの記録には別途設定が必要 | デフォルトでは無効。未設定のホストではイベント自体が記録されない |
| Security | `4672` | デフォルトで有効 | 特権を持つログオンへの特別な特権の割り当てを記録する | 今回挙げられたイベントの中では、デフォルトで記録されるもの |
| Security | `4673` | Audit Sensitive Privilege Use（機密性の高い特権使用の監査）を有効化 | 特権サービスの呼び出しを記録する | `SeImpersonatePrivilege` は対象だが、Potato 系ツールが使用する通常の名前付きパイプ経由の偽装は監査対象の特権サービス経路を通らないため、通常は記録されにくい |
| Security | `4674` | Audit Sensitive Privilege Use（機密性の高い特権使用の監査）を有効化 | 特権オブジェクトに対する操作の試行を記録する | 特権オブジェクトへの操作を調査する際に使用する |
| Security | `4703` | Audit Token Right Adjusted（トークンの権限変更の監査）を有効化 | プロセス自身のトークン内で特権が有効化されたことを記録する | `Disabled → Enabled` の変化を検出できるが、非常にノイズが多い。Potato 系ツールは最初から特権が有効な SYSTEM トークンでシェルを起動するため、この昇格処理自体では通常発生しない |
| Sysmon | `1` | Sysmon のインストールとプロセス作成イベントの設定が必要 | プロセスの作成を記録する | Security `4688` と併せてプロセスの親子関係や実行経路を調査できる |
| Sysmon | `10` | Sysmon のインストールとプロセスアクセスイベントの設定が必要 | プロセス間のアクセスを記録する | トークンの窃取やプロセスへのアクセスの調査に利用できる |
| Sysmon | `17` / `18` | Sysmon のインストールと名前付きパイプイベントの設定が必要 | 名前付きパイプの作成（17）および接続（18）を記録する | Potato 系ツールが使用する名前付きパイプの動作を調査する際に利用できる |

### sysmon 1 プロセス作成、（Security 4688）

- 権限昇格ツールの起動（services.exe 以外の親。w3wp.exe 等）
- SYSTEM ユーザーの cmd 等の子プロセス起動（親が権限昇格ツール）

### Sysmon 17、18 名前付きパイプ（作成、パイプ接続）

- \pipe\spoolss パイプが、spoolsv.exe 以外のプロセスから作成されている

### Security 4672 新しいログオンに割り当てられた特別な権限

- Webサービスアカウントなどのサービスログインでも頻繁に生成されるため、単体ではノイズでしかない。
- 重要なのは「イベント4672の発生後に、該当サービスアカウントが名前付きパイプ経由でSYSTEM権限の子プロセスを生成した」という発生順序。
- PrintSpooferなどの昇華ツールで作成されたSYSTEM子プロセスは、サービスアカウントではなくSYSTEM固有のログオンセッション（0x3E7。10進数で 999）で動作するため、Logon IDのチェーンが切断される。
- ネットワークログオン（イベント4624）を探すのではなく、「親プロセスのチェーンからは本来入るはずのないログオンセッションのトークンを持つプロセスが存在する」という不整合を特定することが検知のポイント。

## アーティファクト

なりすましそのものは、いかなるアーティファクトにも記録されない。

実行ファイルを実行したこと（Prefetch等）、実行ファイルの履歴（ジャーナル）は調査できる。
