# チケット検出

https://tryhackme.com/room/krbticketattacks

## 基礎

### 認証の流れ

#### ユーザーを検証してTGTを発行する。

1. AS-REQ
2. AS-REP

TGT は KRBTGT アカウントのキーで暗号化される。

#### TGTを検証してサービスチケットを発行する。

3. TGS-REQ
4. TGS-REP

サービスチケットはターゲットサービスアカウントのキーで暗号化される。

#### サービスを要求する。

5. AP-REQ

チケットを封印する鍵を盗めば、存在しないユーザーを含め、任意のユーザーのチケットを自分で作成できる。

### シルバー、ゴールデン、ダイヤモンドの違い

| 項目 | **Silver（シルバー）チケット** | **Golden（ゴールデン）チケット** | **Diamond（ダイヤモンド）チケット** |
| :--- | :--- | :--- | :--- |
| 目的 | 1つのサービスへの目立たないアクセス | ドメイン侵害後の永続的なアクセス確保 | Golden Ticket の検知を回避したドメインアクセス |
| 必要な権限 | 任意のドメインユーザー | Domain Admin または同等の権限 | Domain Admin または同等の権限 |
| 必要な情報 | サービスアカウントのハッシュ | KRBTGT のハッシュ | KRBTGT の AES キーと有効な認証情報 |
| アクセス範囲 | 1つのサービス、1台のホスト | ドメイン全体 | ドメイン全体 |
| ドメインコントローラー（DC）からの見え方 | 何も検知されない | DC が発行していない TGT が使用される | DC が実際に発行したチケットが使用される |

具体的なコマンドは Kerberos.md 参照。

## シルバーチケット検出

### Security 4624（ログオン）

- ログオンタイプ3 （ネットワークログオン）
- LogonGuid: 偽造チケットの場合、多くの場合すべてゼロ。または上流イベントと一致しない。

```sh
Get-WinEvent -FilterHashtable @{Path="C:\Evidence\Silver\LB-SQL01-Security.evtx"; Id=4624} | Where-Object { $_.Message -match "Logon Type:\s+3" }
```

### Security 4769（DCに TGS が要求された）

4624イベントのアカウント名とタイムスタンプを、DCの 4769 イベントと比較する。正規のサービスアクセスでは、DC上で 4769 イベントが記録されているはず。

```sh
Get-WinEvent -FilterHashtable @{Path="C:\Evidence\Silver\LB-DC01-Security.evtx"; Id=4769}
```

### 暗号化のダウングレード

RC4 が要求されるのは異常のシグナル。 ***ADモニタリング.md を参照。***

### プロセス実行痕跡

サービスサーバではなく、ワークステーション側のプロセス実行痕跡を探す。例えばRubeusなど。

## ゴールデンチケット検出

| 検出のポイント（特徴） | 発生場所 | 関連するイベントIDと動作概要 |
| :--- | :--- | :--- |
| **正常なフローの欠落**<br>（4768の非発生） | ドメインコントローラー（DC） | **TGS要求（ID 4769）があるにもかかわらず、TGT要求（ID 4768）が存在しない**<br>※DCが自ら発行していない改ざん・偽造されたTGTが使用されていることを示す。<br>※端末側では特権アクセス時に **ID 4624**（ログオン）や **ID 4672**（管理者特権の割り当て）が記録される。 |
| **チケットの異常値**<br>（アーティファクト） | チケットの内容<br>（Kerberosチケット） | **チケットの有効期限が10年など異常に長い、またはAES環境下でRC4暗号化が使われている**<br>※偽造チケット作成ツール（Mimikatz等）のデフォルト設定やパラメータの異常に起因する。 |
| **事前のドメイン複製動作**<br>（攻撃の前提段階） | ドメインコントローラー（DC） | **ID 4662（オブジェクトへのアクセス）**<br>※ゴールデンチケット作成に必要な「krbtgt」アカウントのハッシュ（DS-Replication-Get-Changes / GUID）をDCから不正取得（DCSync攻撃）した際に上流工程で記録される。 |

## ダイヤモンドチケット検出

| 検出のポイント（特徴） | 発生場所 | 関連するイベントIDと動作概要 |
| :--- | :--- | :--- |
| **正規ログの生成**<br>（正常なフローの存在） | ドメインコントローラー（DC） | **TGT要求（ID 4768）が正常に発生**<br>※ゴールデンチケットと異なり、暗号化用証明書（PAC）の偽造によって正規のDCから有効なTGTを取得するため、ID 4768が記録される。<br>※チケットの有効期限や暗号化方式（AES）も正常な値を示す。 |
| **特権アクセスの実行**<br>（昇格した権限の使用） | 攻撃対象のホスト | **管理者特権の割り当て（ID 4672）**<br>※偽造されたPAC情報に基づき、対象ホスト上で管理者権限が与えられた際にログオンイベントとともに記録される。 |
| **グループ追加ログの欠落**<br>（ログとディレクトリの不整合） | ドメインコントローラー（DC） | **グループ追加ログ（ID 4728 / 4732 / 4756）が存在しない**<br>※特権グループ（Domain Admins等）へアカウントを追加した形跡ログがないまま、管理者権限が行使される。 |
| **ADデータベースとの不一致**<br>（矛盾の検出） | Active Directory（ADエクスポート） | **AD上のグループメンバーシップ情報との矛盾**<br>※DCのデータベース（NTDS.dit）を抽出・確認した際、対象アカウントが該当する特権グループのメンバーとして登録されていないことが判明する。 |
