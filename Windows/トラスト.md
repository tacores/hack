# トラスト

https://tryhackme.com/room/activedirectorytrusttheory

重要な原則：フォレストはActive Directoryにおけるセキュリティ境界である。ドメインは管理上の境界であり、セキュリティ上の境界ではない。

## 基礎

Active Directory のすべての信頼関係は、一対の信頼済みドメインオブジェクト (TDO)によって支えられている。

各TDOは下記のような情報を保持する。

- trustPartner パートナードメインのDNS名。
- trustDirection （このドメインの観点から）受信、送信、または双方向を示す整数。
- trustType 信頼技術を分類する整数。
- trustAttributesSID フィルタリング、選択的認証、フォレスト推移性などの動作を制御するフラグのビットマスク。
- TDOに暗号化されて保存される信頼パスワード（共有シークレット） レルム間Kerberosチケットを暗号化する信頼キーを生成するために使用される。

単一の信頼関係では、常に2つのTDOオブジェクトが生成される。

### trustType

| **Value** | **Name**  | **意味**                                |
| --------: | --------- | ------------------------------------- |
|         1 | Downlevel | Windows NT ドメイン、2000 年以前              |
|         2 | Uplevel   | Active Directory ドメイン、Windows 2000 以降 |
|         3 | MIT       | Windows 以外の Kerberos レルム              |
|         4 | DCE       | 歴史的な方式、現在ではほとんど見られない                  |

### trustDirection

| **Value** | **Name**      | **意味（ローカルドメインから見た視点）**                                         |
| --------: | ------------- | -------------------------------------------------------------- |
|         1 | Inbound       | 相手側ドメインがこのドメインを信頼する。このドメインのユーザーが相手側のリソースにアクセスできる。アクセスは外向きに流れる。 |
|         2 | Outbound      | このドメインが相手側ドメインを信頼する。相手側のユーザーがこのドメインのリソースにアクセスできる。アクセスは内向きに流れる。 |
|         3 | Bidirectional | 双方向。どちらの方向でもアクセスできる。                                           |

### trustAttributes

| **Flag**              | **Hex** | **Decimal** | **意味（運用上の意味）**                                                                                                                     |
| --------------------- | ------: | ----------: | ---------------------------------------------------------------------------------------------------------------------------------- |
| `NON_TRANSITIVE`      |   `0x1` |           1 | 信頼関係が接続された2つのドメインを越えて拡張されない。外部信頼やショートカット信頼で一般的。                                                                                    |
| `UPLEVEL_ONLY`        |   `0x2` |           2 | この信頼関係では、Windows 2000 以降の認証のみが許可される。                                                                                               |
| `QUARANTINED_DOMAIN`  |   `0x4` |           4 | SID フィルタリングが適用される。PAC 内に含まれる信頼されたドメインに属さない SID は削除される。外部信頼ではデフォルトで設定される。フォレスト信頼では、このフラグが明示的に設定されていなくても DC 側のロジックによってフィルタリングが適用される。 |
| `FOREST_TRANSITIVE`   |   `0x8` |           8 | フォレスト信頼であることを示す。両方のフォレスト内にあるすべてのドメインに対して信頼が推移する。                                                                                   |
| `CROSS_ORGANIZATION`  |  `0x10` |          16 | 選択的認証（Selective Authentication）が適用される。アクセスには、対象リソースに明示的な `Allowed-To-Authenticate` ACE が必要。                                        |
| `WITHIN_FOREST`       |  `0x20` |          32 | フォレスト内信頼（Intra-forest trust）。SID フィルタリングは無効。フォレスト内で完全な推移性を持つ。このため ExtraSids 攻撃が可能になる。                                              |
| `TREAT_AS_EXTERNAL`   |  `0x40` |          64 | フォレスト信頼に適用され、SID フィルタリングを緩和する。RID が `1000` 未満の SID のみが削除され、RID が `1000` 以上の外部 SID は残る。                                             |
| `USES_RC4_ENCRYPTION` |  `0x80` |         128 | 信頼関係のキーに AES ではなく RC4 暗号化を使用する。                                                                                                    |
| `NO_TGT_DELEGATION`   | `0x200` |         512 | この信頼関係を越えた TGT 委任をブロックし、信頼関係をまたいだ非制約委任（Unconstrained Delegation）の悪用を防止する。                                                          |
| `PIM_TRUST`           | `0x400` |        1024 | Privileged Identity Management（PIM）信頼。Bastion Forest / MIM PAM シナリオで使用される。                                                         |

### 推移性

trustAttributes のビットに含まれる。

- 推移的信頼：信頼関係は、参加する2つのドメインを超えて、信頼チェーンを通じて到達可能なすべてのドメインにまで及ぶ。ドメインAがドメインBを信頼し（推移的）、ドメインBがドメインCを信頼する場合（推移的）、ドメインAは暗黙のうちにドメインCを信頼することになる。
- 非推移的信頼：信頼は参加する2つのドメインに厳密に限定される。連鎖は発生しない。

### トラストキー

トラストキー（インターレルムキーとも呼ばれる）は、レルム間Kerberos認証を機能させるための共有秘密鍵。これは、各ドメインのTDOに保存されているトラストパスワードから生成される。

- ADはTDOを内部的にマシンアカウントのように扱う。信頼パスワードは、ドメインのMaximumPasswordAgeマシンアカウントポリシーに従って、約30日ごとに自動的に更新される。
- 現在および以前の信頼キーは常に保持される。これにより、古いキーで暗号化された機内紹介チケットは、ローテーション期間中も有効であることが保証される。
- 攻撃者の視点から見ると、信頼キーのダンプは、レルム間チケットを偽造するための前提条件。信頼キーがあれば、注入された ExtraSid を含む任意の PAC コンテンツを持つ紹介 TGT を作成できる。

### 信頼できるDCが行う3つのチェック

信頼するドメインコントローラー（リソースドメイン内のドメインコントローラー）が参照TGTを受信し、サービスチケットを発行する準備をする際、PACを盲目的に信頼するわけではありません。3つのセキュリティチェックを実行します。

1. SID フィルタリング。信頼するドメインコントローラーは、PACExtraSidsとResourceGroupDomainSidフィールドを調べます。信頼タイプとtrustAttributesフラグに基づいて、信頼されたドメインが主張できない SID を削除 (フィルタリング) します。たとえば、デフォルト設定のフォレスト信頼では、ドメインコンポーネントが信頼されたフォレスト内のドメインと一致しない SID は削除されます。これは、あるフォレスト内の侵害された子ドメインが別のフォレストの Enterprise Admins SID を挿入するのを防ぐ主要なメカニズムです。

2. TGT委任チェック。信頼関係にtrustAttributesフラグNO_TGT_DELEGATION が設定されている場合、信頼するドメインコントローラーは発行されたサービスチケットにフラグを設定しません。これにより、信頼境界を越えた制約なし委任の悪用を防ぎます。フラグがない場合、クライアントはTGTをサービスに転送しないため、古典的な制約なし委任攻撃が信頼関係を越えるのを阻止します。

3. 選択的認証。信頼関係で選択的認証が有効になっている場合（ のCROSS_ORGANIZATIONフラグ、0x10で示されるtrustAttributesか、信頼関係プロパティの UI で構成）、信頼する DC は追加の承認チェックを実行します。認証を行うユーザーが、信頼するドメイン内の対象コンピューター オブジェクトに対してAllowed-To-Authenticate拡張権限を持っているかどうかを確認します。権限が付与されていない場合、ユーザーが持つ他の権限に関係なく、認証は即座に拒否されます。選択的認証は、信頼関係を「すべての認証済みユーザーに公開」から「コンピューターごとに明示的に承認されたプリンシパルにのみ公開」に効果的に変換します。

#### 意思決定

- WITHIN_FOREST (0x20) が設定されています: SID フィルタリングは無効です。ExtraSIDs 攻撃は有効です。
- FOREST_TRANSITIVE (0x8) かつ QUARANTINED_DOMAIN (0x4) がない場合：フォレスト間の信頼関係では、SID フィルタリングがデフォルトで有効になっているはずです。隔離フラグが実際に存在せず、フィルタリングが適用されない場合は、何らかの設定ミスがあります。ExtraSids がフォレスト間で機能すると想定する前に、必ず確認してください。
- QUARANTINED_DOMAIN (0x4) が設定されました: SID フィルタリングが有効です。ExtraSids は削除されます。代替ベクトルに切り替えます: クロストラスト Kerberoasting、委任の悪用、外部グループへの所属。
- NO_TGT_DELEGATION (0x200) が設定されています:この信頼境界を越えた制約のない委任の悪用はブロックされます。このベクターはスキップします。
- フォレスト信頼関係で TREAT_AS_EXTERNAL (0x40) を指定すると、 SID フィルタリングが緩和されます。RID が 1000 未満の SID のみが削除されます。RID が 1000 以上の SID はフィルタを通過します。これにより、カスタムグループ (常に RID が 1000 以上) を PAC に挿入できるため、権限昇格の経路が開かれます。
- CROSS_ORGANIZATION (0x10) が設定されています:選択的認証が有効になっています。各ターゲットリソースには、外部プリンシパルへのアクセスを許可する明示的な「Allowed-To-Authenticate」ACE が必要であり、これにより攻撃対象領域が縮小されます。

## フォレスト内横断（ExtraSids）

dev.corp.thm のドメイン管理者権限を持っているとして、フォレストルート corp.thm のエンタープライズ管理者を目標とする。

### 前提条件

- dev.corp.thm の krbtgt NTLMハッシュ（DCSync）
- dev.corp.thm のドメインSID 
- 対象グループのSID。エンタープライズ管理者の場合、corp.thmドメインSIDにRID 519を付加したもの。

519は監視が厳しい。ステルスSIDとして、ドメインコントローラーグループ (RID 516)、エンタープライズドメインコントローラー(S-1-5-9)も検討。

## フォレスト間攻撃

フォレスト間トラストは外部SIDがフィルタリングされるため、ExtraIds攻撃は使えない。
